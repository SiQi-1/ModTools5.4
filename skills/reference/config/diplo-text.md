# 外交文本

## 原理

外交文本通过 **LOC 键命名匹配**自动生效，无需在 SQL/XML 中显式绑定。游戏引擎根据当前场景 + 领袖标识，按约定的键名格式查找对应文本。有默认文本的场景可省略。

## 键名格式

```
LOC_DIPLO_<场景>_LEADER_<领袖标识>_ANY
```

`<领袖标识>` 即领袖 Type 去掉 `LEADER_` 前缀。如 `LEADER_SQ_L0037_1` → `SQ_L0037_1`。

## 写法

所有外交文本写在一个 INSERT 块中，放在 `Text/<ModName>_Text_CN.sql` 末尾：

```sql
-- 外交文本
INSERT INTO LocalizedText (Language, Tag, Text) VALUES
('zh_Hans_CN', 'LOC_DIPLO_GREETING_LEADER_SQ_L0037_1_ANY', '欢迎，远方的旅人。曦光照耀之地，皆是朋友。'),
('zh_Hans_CN', 'LOC_DIPLO_FIRST_MEET_LEADER_SQ_L0037_1_ANY', '我是曦，曦和文明的守护者。愿我们的相遇如晨曦般美好。'),
-- ... 按需继续
;
```

## 议程必需的保底文本

以下两条**必须写**，否则议程文本不会正常显示：

| 场景 | LOC 键格式 |
|------|-----------|
| 警告后退出 | `LOC_DIPLO_WARNING_EXIT_LEADER_XXX_ANY` |
| 赞赏的议程原因 | `LOC_DIPLO_KUDO_LEADER_XXX_REASON_AGENDA_YYY` |
| 谴责原因 | `LOC_DIPLO_WARNING_LEADER_XXX_REASON_ANY` |

`XXX` = 领袖标识，`YYY` = 议程名称。示例：
```
LOC_DIPLO_WARNING_EXIT_LEADER_SQ_L0037_1_ANY
LOC_DIPLO_KUDO_LEADER_SQ_L0037_1_REASON_AGENDA_SQ_L0037_1
```

## 规则

1. **只写需要的场景**，有默认文本的不用写
2. **不必写全 48 个**——先写最常见的（打招呼、初次见面、宣战、谴责），其余按需追加
3. **键名严格匹配**，拼错不会生效，也不会报错
4. 文本中可嵌入 `[ICON_xxx]` 图标
5. 新建领袖时，将 `XXX` 替换为实际领袖标识
