# 明日方舟系列：上传前准备

仅用于明日方舟题材的文明6 Mod。用户确认的能力文本、数值、角色命名优先；不要把实现说明和测试清单写进玩家能力。上传前准备不包含上传操作。用户只要求这些材料时，完成本地材料和已授权的工程交付即可。

## 1. 冻结当前中文

玩法与中文文本基本定稿后再集中补英文，避免反复翻译变动规则。先重新导出当前 `.CIV`，从实际中文 `LocalizedText` 生成 Tag 清单，包含：文明/领袖、Name 与 Description、所有能力和特色内容、百科、相邻提示、外交、城市名、市民名、UI 文本及其他扩展文本。Mod 列表 Name/Teaser/Description 的英文元数据另行核对，不算作完整游戏翻译。

将中文快照和中英 Tag 对照保留在本 Mod 工作目录。导出后中文变动时，以差异更新翻译；不能拿旧设计稿覆盖用户已经修改的玩家文本。

## 2. 英文文本

- 核实干员代号、真名、地名、皮肤和原作专名的官方英文。没有可靠专名时使用清楚的含义翻译，并记录依据；不可把自动音译当成官方名。人物资料查证与文明6术语翻译分开处理。
- 原样保留 LOC Tag、`{1_Amount}` 等参数、格式控制符和必要的 `[ICON_*]`。数字、正负号、百分比、距离、解锁条件与中文一致。专有名称自身的数字需要区分语义；不靠单一数字正则替代人工核对。
- 用户指定不加图标的 UI 文案保留该例外，例如“+X 来自文化值转化”。其余入游戏的能力文本遵循通用图标流程。
- 使用工具的原生多语言入口。当前实体自定义文本只支持当前语言时，通过 `modgen extension write --role text --scope both` 纳管额外 `en_US` SQL；不要改生成的中文文件，也不要只在 ModBuddy 输出中维护英文。`both` 使选人界面和游戏内都加载，实际仍需检查生成动作。
- SQL 字符串单引号转义；检测重复 Tag、缺译、错用语言代码、残留中文、占位符和图标变化。用 SQLite 加载中英文确认每个中文 Tag 有一个英文值，外部原版 LOC 引用另行解析。

## 3. 双语封面

布局为背景＋角色立绘＋长方形黑幕＋中文标题和英文标题。优先使用已确定的明日方舟背景与皮肤素材；外交立绘的固定规则不约束封面。用户给定封面文字时逐字采用，不由封面文字反向重命名游戏内容。

模板：`assets/leader-cover.psd`，原名“封面模版领袖.psd”，来自用户的 `111商单合集`。512×512，`矩形 1` 为黑色矩形形状层，透明度 168/255，带细白描边；实际矢量边界与缓存层 bbox 略有区别，导出使用矢量重绘，不能只用合并预览当蒙版。用户确认此套社区模板可纳入 Git 和分享，作者暂不可考；没有已知许可证文本，不自行标注 MIT/CC0。原文件 SHA-256：`e82efa16f689f2368a83cb572429d07fb4a036fa24147a78dcef0004e3030bb7`。

先查看素材和 PSD 层级，确认指定黑幕层。配方路径相对于配方文件；字体用目标机器已存在的完整路径（不随技能分发字体）：

```json
{
  "template_psd": "path/to/leader-cover.psd",
  "curtain_layer": 0,
  "background": "background.png",
  "background_focus": [0.5, 0.5],
  "foreground": "standing-art.png",
  "foreground_transform": {"scale": 0.6, "x": -255, "y": -340},
  "text_margin": 20,
  "text": [
    {"name": "Chinese title", "value": "明日方舟：角色", "font": "C:/Windows/Fonts/msyhbd.ttc", "size": 52, "top": 344},
    {"name": "English title", "value": "Arknights: Character", "font": "C:/Windows/Fonts/arialbd.ttf", "size": 36, "top": 421}
  ]
}
```

这些位置仅为示例，不能跨角色盲用；脚本的文字定位以可见字形顶部为准。需要 Pillow 与 psd-tools（composite 支持）：

```powershell
python scripts/render_cover.py cover-recipe.json --out output/cover
```

输出原模板尺寸 PNG、1024 PNG、256 预览、分层 PSD 和散列记录。1024 版从原始图片重新采样，不是把 512 成品放大。原模板矢量黑幕保留，背景/立绘/两行文字分层；文字是栅格层，编辑配方可重排，不宣称为 Photoshop 活文字层。已有输出需保留版本后使用 `--replace`。

脚本不做人脸定位，不理解人物焦点，不重画立绘。视觉模型或人工检查：脸部位置、头发及角色关键轮廓裁切、黑幕是否压脸、标题准确性、256 小图可读性。没有视觉能力的 AI 只能复用同一素材已验收的坐标或交付明确标为待视觉复核的候选。换图、换字体、改裁切后必须重看；脚本成功不等于视觉验收。任意 PSD 的复杂效果不在此脚本支持范围内。

## 4. 工坊描述

中英各一份 UTF-8 文本，从刚核对的能力文本生成。去除仅游戏字体能解释的 `[ICON_*]`，将 `[NEWLINE]` 转成换行；不能删除正常标点、百分比或能力条件。不追加实现链路、作者推断、宣传口号。用户模板中的 `[code]` 原样保留，未经要求不改 Steam 格式。

```text
[hr][/hr]
[code]
[h1]文明：<文明名>[/h1]
[hr][/hr]
[h2]领袖：<领袖名>[/h2]
[hr][/hr]
[h3]文明能力：<名称>[/h3]
<能力描述>
[h3]领袖能力：<名称>[/h3]
<能力描述>
[h3]特色区域：<名称>[/h3]
<能力描述>
[h3]特色改良设施：<名称>[/h3]
<能力描述>
[/code]
[hr][/hr]
```

英文对应 Civilization / Leader / Civilization Ability / Leader Ability / Unique District / Unique Improvement。按该 Mod 实际特色类型替换标题；不能给所有 Mod 强加区域＋改良组合。文本数量沿用已确认设计。

## 5. 交付核对

重新导出、编译并按已有授权交付。检查两语言 Tag 集合、实际 SQL 装载、两种作用域的 UpdateText、Mod 元数据、图标/参数/数值一致；将现用中文与冻结快照比较，避免翻译期间发生遗漏。

封面查看 PNG 和 PSD 重新合成图；至少查看原尺寸与 256 缩略图。保留配方、输入来源、字体路径、输出尺寸、散列和视觉复核记录。工坊中英各自检查 BBCode 配对、顺序、特色数量、无游戏图标符号和无占位文字。

给用户封面、分层源文件、两份可直接复制的工坊描述及已补英文的工程/发布包。说明静态/编译检查和游戏内待验收边界。发布页点击提交、SteamCMD 上传等需要独立的用户上传指令；本流程到本地材料准备完成为止。
